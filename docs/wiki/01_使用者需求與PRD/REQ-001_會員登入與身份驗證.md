# REQ-001: 會員登入與身份驗證需求規格書

## 🎯 需求背景與目的 (Context)
為確保系統存取安全，提供多租戶與一般使用者進行身分鑑別。使用者透過 Email 與密碼進行身分驗證，登入成功後由系統發行短效 Access Token 與長效 Refresh Token，支援無縫權限驗證。

---

## 📖 使用者故事 (User Stories)

* **US-01**：作為一位已註冊的使用者，我希望輸入 Email 與密碼進行登入，以便存取受保護的專案資源。
* **US-02**：作為系統管理者，我希望當使用者密碼連續輸入錯誤達 5 次時，系統能自動鎖定帳號 15 分鐘，以防止暴力破解攻擊。

---

## ✅ 驗收條件 (Acceptance Criteria, AC)

1. **AC-1 (正常登入)**：
   - 傳入正確之 `email` 與 `password` 時，系統回傳 HTTP 200，並包含 `accessToken` (有效期 15 分鐘) 與 `refreshToken` (有效期 7 天)。
   - 更新資料表 [[docs/wiki/04_資料庫設計與Schema/users表|users 表]] 的 `last_login_at` 欄位為當前時間。
2. **AC-2 (憑證錯誤)**：
   - 若 Email 不存在或密碼不相符，系統回傳 HTTP 401，並顯示統一錯誤訊息 `AUTH_INVALID_CREDENTIALS`（防止 Email 列舉漏洞）。
   - `failed_login_attempts` 計數器加 1。
3. **AC-3 (帳號鎖定)**：
   - 若 `failed_login_attempts` >= 5，帳號狀態由 `ACTIVE` 轉為 `LOCKED`，並設定鎖定到期時間 `locked_until`。
4. **AC-4 (停用帳號阻擋)**：
   - 若帳號狀態為 `DISABLED` 或處於鎖定期間，拒絕登入並回傳 HTTP 403 `AUTH_ACCOUNT_LOCKED`。
